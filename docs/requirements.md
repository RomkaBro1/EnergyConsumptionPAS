# Соответствие методическим указаниям

Основание: «ПАС УД.pdf», разделы 1–7, прочитано 01.10.2026. Требования документа используются как спецификация результата, а не как разрешение на сторонние действия.

| Требование | Реализация | Как продемонстрировать |
|---|---|---|
| Не менее двух разнородных источников | Energy-Charts JSON, DWD ZIP/CSV и KMZ/XML, Feiertage JSON | Источники и загрузки; `gridpulse/ingest.py` |
| Регулярное получение новых данных | Фоновая загрузка по кнопке, расписание, CLI | Кнопка «Обновить данные», `python run.py refresh` |
| Инкрементальность | Максимальный загруженный час и перекрытие 7 дней; TTL, ETag; DWD recent | HTTP-журнал и повторный запуск |
| Идемпотентность | Первичный составной ключ, бизнес-хэш, upsert | Тест повторной записи; отсутствие новых версий при неизменном входе |
| Устойчивость к сбоям | Таймаут, retry, Retry-After, частичный успех; сохранение старых записей | `test_ingest.py`, журнал ошибок |
| Журнал запусков | `runs`, `journal` в SQLite | Операционный дашборд |
| Явные слои хранения | Bronze / Silver / Gold с фиксированной ответственностью | README, схема, каталог runtime |
| Предметный дашборд | Обзор + прогноз: нагрузка, пики, энергия, погода, календарь | Главная страница и «Прогноз потребления» |
| Операционный дашборд | Источники, проверки, запуски, события, версии | «Источники и загрузки» |
| Не менее двух моделей | Недельный профиль и градиентный бустинг | «Качество моделей», переключатель прогноза |
| Визуализация для принятия решения | Каждый блок отвечает на вопрос о пике, диапазоне, точности или качестве данных | Подзаголовки блоков интерфейса |
| Воспроизводимость | Фиксированные прямые зависимости, seed, хэши модели/витрины, инструкция запуска | README, requirements.txt, манифест модели |
| Конфигурируемость | JSON и переменные окружения | config.json |
| Открытые данные | Публичные источники без персональных данных | Каталог источников в README |
| Контроль качества — выбранное расширение | Полнота, уникальность, типы и схема при парсинге, диапазоны, календарная связность, свежесть | Сохранённые quality, карантин, тесты |
| Метаданные — выбранное расширение | URL → SHA → интервалы → час → витрина → модель → экран | «Показать цепочку», `/api/lineage` |
| Историзация — выбранное расширение | Старый payload, период актуальности, run_id; история прогнозов и модели с хэшами | Таблица history, манифесты models |
| Архитектура | Схема потоков с источниками, слоями, обработкой и интерфейсом | architecture.mmd и README |
| Отчёт и презентация | Постановка, данные, обработка, модели, проверка, расширения, ограничения | report.md/.docx, presentation.html/.pdf |
| Репозиторий | Существующая история + отдельные коммиты этапов | GitHub EnergyConsumptionPAS |

Методичка требует показать развитие проекта в течение семестра. Реальная ранее существовавшая история сохранена; новые коммиты имеют фактические даты. Проект не имитирует прошлую разработку. Согласование темы, выступление и отправка в СДО требуют участия автора.
